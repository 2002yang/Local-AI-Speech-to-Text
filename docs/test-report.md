## 实时识别验证

- 自动化覆盖停止前返回文字、序号顺序、尾段刷新、整段最终校正、静音、非法初始化及 PCM、模型缺失、推理失败、队列满明确报错、服务端 60 秒上限、断连重连及跨来源拒绝。
- 最新真实模型 WebSocket 测试：中文和英文均在发送 stop 前得到非空预览；停止后返回全文校正。中文样本最终为“你好，欢迎使用本地语音识别系统。今天的天气很好，我们一起测试中文语音转文字。”；英文最终仍含模型既有拼写误差 `Wecome`。该轮累计推理耗时分别约 1.499 秒、1.237 秒，包含最终校正，不是首字延迟或录音总耗时。
- 浏览器以样本经 AudioContext → MediaStreamDestination → AudioWorklet → WebSocket → 真实模型，验证中英停止前出字与有序尾段。48 kHz 输入有效；工作线程算法模拟在 16/44.1/48/96 kHz 输入下，一秒均输出 16000 样本。这些是样本驱动验证，不是真人麦克风。
- 代理的浏览器样本实测发生在加入全文校正之前；最新全文校正版本已通过后端真实模型测试，随后用户确认实际实时中英文使用正常，作为真人核心流程验收结果。
- 用户本次未单独说明实时模式 60 秒自动停、断网实时、连续录音及异常恢复各项细节；不把总体“没问题”扩展为这些边界逐项通过。普通模式 60 秒与断网已有确认，实时服务端时长边界有自动化覆盖，不再将扩展手动测试作为继续开发的前提。

## 已知风险与未完成验证

- 已修复 `.weba` 上传被误拒绝：用户提供浏览器保存的 `中文语音.weba`，检查为有效 WebM/Opus、286059 字节、17.7 秒。原先扩展名白名单遗漏 `.weba`，返回 415；现已接纳该别名，仍执行真实容器/编码及长度校验。修复后通过 TestClient 调真实本地模型返回 200 和中文文本，处理约 3.183 秒，开头为“这是一个你说话就能出现文字的网页。”。新增大小写扩展名、真实 WebM 内容和损坏内容回归测试；不复制用户私人录音到测试夹具或交付包。

- 已定位用户约 17 秒中文录音返回空文字的问题：Chrome 独立选择了“立体声混音 (Realtek(R) Audio)”而非物理麦克风，Windows 系统默认麦克风正确并不代表 Chrome 选择正确。用户切换为“Microphone Array (Realtek(R) Audio)”后，音量条随讲话变化，确认可识别语音。该问题不是模型未接入。排查中新增了实时输入音量、录音本地回放、采集峰值及用户主动下载，不自动持久化真人录音。更新后常规测试 20 通过、4 跳过，页面无 error 级别控制台错误。

- 合成测试语音不能代替真实真人麦克风音频；用户已明确同意随公开仓库发布两份 WAV，来源与第三方许可尚未独立核实的边界见 `samples/SOURCE.md`。用户同意不构成第三方许可证明，不宣称样本许可合规已完全核实。
- 固定时间窗选择低能量切分对无停顿语音可能截断词；33 秒拼接英语样本已通过，但更多长段实录未测。
- 实时短分段可能有断词、重复字或标点误差；全文校正能改善上下文，但不保证完全正确。真人实时核心使用验收已有用户确认；干净环境复现尚未执行，样本第三方条款核实边界如上，不代表仍需开发功能。
- 本机样本首次中英文请求约 2–2.6 秒，33 秒拼接英语约 1.9–2.2 秒；Windows 进程采样工作集约 694 MiB（只作该次观察，不等于严格峰值测量）。
- FastAPI/Starlette 当前依赖在 pytest 中发出 `httpx` TestClient 弃用警告，不影响测试通过。
- 首次启动 8000 端口被本机酷狗音乐占用，用户终止酷狗后已成功使用规定端口；如再次遇到端口冲突，需释放 8000，不应更改题目约定命令。
