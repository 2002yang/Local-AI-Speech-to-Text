## 1. 目标与范围

交付一个可以在 Windows 11 x64 普通 CPU 电脑上独立复现的 B/S 系统：浏览器录制或上传音频，本地模型识别中文或英文，页面显示文字及耗时。

### 第一阶段：完成全部必做要求

- F1：浏览器麦克风录音，开始、停止、状态与计时，最长 60 秒，停止后识别，支持再次录音。
- F2：上传 WAV 和浏览器实际录音格式，两种来源共用后端识别逻辑。
- F3：真实本地模型中英文识别，页面语言选择实际传入推理层，不做翻译，支持连续多次识别。
- F4：显示选择的语言、当前状态、识别文字、实际音频时长、服务端处理耗时，并支持复制文字。
- F5：明确处理权限、设备、文件、时长、模型及后端异常；错误后可恢复操作。
- 完成自动化测试、真实模型验证、指定手动验证、文档与 OpenCode 开发证据。

已确认的时长边界：浏览器录音仍在 60 秒自动停止；上传音频及统一转写接口按实际解码时长设置 65 秒上限，为浏览器编码与封装留出缓冲。接受不超过 65 秒的音频，超过时明确返回 HTTP 4xx，不静默截断。65 秒是本项目经用户确认的边界，不是原题规定。

### 后续阶段：实时识别加分项

最初安排在必做验收后实施；用户确认普通录音、60 秒自动停和断网识别可用后，明确授权开始实时实现。目前实现及自动化/真实模型测试已完成，用户确认实时中英文正常；P5 提交收尾及未单独验证的边界如实记录。

实际采用浏览器 AudioWorklet PCM 分片、WebSocket、简单能量门控/有界分段、本地模型识别和增量文字展示，停止后处理尾段并额外做一次整段最终校正。保留普通录音模式及其“停止后才进行完整识别”的行为。能量门控不是神经网络 VAD；最终校正是针对实测断词误差增加的实现细节。

自动检测语言、中英文混合识别同属加分项，不替代必做的 `zh` / `en` 选择。

### 本次范围边界

按原题第 8 节控制范围：不增加登录、数据库、历史记录、声纹与说话人识别、自研降噪、翻译、TTS、模型训练、多用户分布式系统、移动端适配或商业级字幕性能目标。

### 选型理由

SenseVoiceSmall 覆盖中文、英文和语言指定；非自回归结构适合 CPU 短音频任务；sherpa-onnx 提供本地推理、Windows 支持及 Python 接口，便于控制依赖规模。

优先参考 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 与 [SenseVoice](https://github.com/FunAudioLLM/SenseVoice) 的模型接口和音频处理示例，不引入 AIAvatarKit 整套语音对话框架。

## 4. 接口契约

### GET /health

正常返回 HTTP 200：

```json
{"status": "ok"}
```

健康检查不触发模型下载。它表示服务可响应；模型未准备就绪时，识别接口应明确返回模型不可用错误，不能因此返回虚假的识别结果。

### POST /api/transcribe

请求为 `multipart/form-data`：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| file | File | 必填，真实可解码的受支持音频 |
| language | String | 必填，仅 `zh` 或 `en` |

成功响应：

```json
{
  "text": "你好，欢迎使用语音识别系统。",
  "language": "zh",
  "duration_seconds": 5.2,
  "processing_seconds": 1.8
}
```

- `language` 返回本次请求选择的语言。
- `duration_seconds` 从实际解码后的音频计算，不能使用推测值，也不能用 VAD 去除静音后的时长替代。
- `processing_seconds` 用单调计时，覆盖必要的校验、解码、重采样和模型推理等本次处理；不包含首次下载模型的时间。
- 无可识别语音时返回空文字并由页面明确提示，不崩溃、不伪造内容。
- 缺失或非法参数、空文件、损坏或不支持格式返回明确的 HTTP 4xx。
- 音频按实际解码时长限制为 65 秒（含），超过上限返回明确的 HTTP 4xx；浏览器录音仍执行 60 秒自动停止。
- 超限文件拟返回 413，不支持格式拟返回 415，参数校验可使用 422；具体错误结构在设计文档固定。
- 模型不可用拟返回 503，推理内部失败返回 500；对用户提供可理解的信息。

### GET /

返回本地 Web 页面。必要时可增加模型状态等接口，但不能替换原题规定接口。
