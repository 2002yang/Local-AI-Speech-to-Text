# OpenCode 开发过程

> 根据本项目真实对话和实现过程填写；后续继续补充测试修复证据，不虚构用户决策或已完成的手动验证。

## 阶段一：需求与方案

使用 OpenCode 阅读腾讯文档《面试考核题-v1》，核对 F1–F5、三个规定接口、Python 3.12 / Windows 11 CPU、pytest、样本、文档及三阶段 AI 使用证据。通过命令检查本机环境（Windows 11、i7-10750H、16 GB 内存、Python 3.12、浏览器和麦克风设备）。比较 Qwen3-ASR ONNX、SenseVoiceSmall ONNX 和 faster-whisper 后，决定用 sherpa-onnx + SenseVoiceSmall ONNX INT8。

用户确认的重要决策：所有项目文件及模型放在当前项目根目录下；普通录音到 60 秒自动停止，上传实际音频最长 65 秒；实时识别后做；按个人面试项目规模实施，不增加生产上线流程。

过程记录：本次 OpenCode 对话、`docs/execution-plan.md` 以及 `docs/requirements.md` / `docs/design.md` 的形成过程。提交会话证据时由用户按需要导出并脱敏。

## 阶段二：功能开发与集成

OpenCode 负责整理模块边界、实现 FastAPI/音频解码/本地模型适配、浏览器普通录音与上传页面、pytest 及模型初始化脚本。选择 sherpa-onnx `from_sense_voice(language=...)` 以保证中文和英文选择实际控制推理；模型目录为项目内 `models/sensevoice-small-int8/`。真实运行及接口验证结果在测试报告中补充。

## 阶段三：测试与问题修复

已执行 `python -m pytest -q`（20 通过、4 项真实模型默认跳过）和 `python -m pytest -q --run-real-model -m real_model -s`（4 通过，含中英文、长音频和实际浏览器 WebM）。浏览器上传中文、英文 WAV 均返回可见识别文字；浏览器生成 WebM/Opus 上传成功。具体输出和未执行项见 `docs/test-report.md`。

一次真实修复：浏览器生成 0.6 秒纯音 WebM 后调用真实模型，发现非语音可能只输出 `。`。检查 `app/asr.py` 结果清理逻辑，新增“只含标点/空格不算文字”的过滤，并加入 `test_punctuation_only_is_not_a_transcript`。重启服务后同样的纯音 WebM 返回 HTTP 200、`text: ""`，与题目“无可识别语音不崩溃”要求相符。

环境问题：规定 8000 端口第一次启动失败；OpenCode 排查监听进程为酷狗音乐，未擅自终止用户进程。用户自行终止酷狗后重试，规定启动命令成功，本机健康接口返回 200。这说明端口冲突属于环境而不是应用接口错误。

证据：`docs/evidence/english-upload-result.jpeg` 为实际浏览器识别页面截图；测试命令、数量、示例识别内容、修复过程记录在本文件和测试报告。OpenCode 会话若作为附件提交，应由用户导出并脱敏，不能把本文件当成会话导出。

真人录音排查：用户反馈中文录音有时长却无文字，系统录音测试能听到声音。OpenCode 重新验证当前 API 的真实中文模型可用，加入浏览器输入音量和本地回放作为诊断；用户最终发现 Chrome 选中了“立体声混音”，切换为 Microphone Array 后音量条变化并成功识别。测试报告按“用户确认成功”记录，不虚构转写文本或耗时。

后续用户报告中英文均可识别、60 秒录音自动停止、断开外网仍可识别。记录为用户实测反馈；具体语言和输入方式的断网组合、转写文本、耗时与截图未提供，不补造证据。

## 实时加分功能实施

用户随后明确授权实现实时语音。OpenCode 按 F6 采用 AudioWorklet PCM 分片、WebSocket、有界能量分段及同一本地模型，增加模式选择、预览与最终结果。未引入 AIAvatarKit。普通模式和三个规定 HTTP 接口继续满足必做路径。

真实样本测试发现 4 秒短段有断词和重复字符，先调整为低能量边界切分，再增加停止后的一次完整音频识别以校正全文；页面明确提示预览会调整。该阶段常规测试 38 通过、6 默认跳过；真实模型测试 6 通过，覆盖中英文停止前出字及最终校正。浏览器样本测试验证 AudioWorklet 链路，后续用户确认实际实时中英文均正常。

2026-10-29 再次读取题目原文，确认 F6 明确允许短分片近实时、无需原生流式或严格毫秒延迟。同步修正 README、需求、设计、测试报告和执行计划中的过时状态，明确实现完成与验收完成的区别。

用户随后反馈浏览器保存的 `.weba` 无法上传。检查实际文件为正常 WebM/Opus，定位为扩展名白名单遗漏，而非 ASR 或录音失败。补充前后端 `.weba` 支持并保留内容校验；真实用户文件经本地模型接口识别成功，常规测试更新为 42 通过、6 跳过。不将用户私人音频存入项目。

用户随后确认实时中文、英文均正常，项目生成的中英文样本上传识别均 OK。以此记录核心使用验收通过并结束功能开发，不继续增加功能；未单独报告的实时边界不补写通过，样本分发权限与源码打包作为提交收尾单列。

用户在本机 CMD 自行运行测试并提供 `42 passed, 6 skipped, 1 warning in 1.54s`。随后授权向 `2002yang` 账号发布公开 GitHub 仓库，并同意公开项目的两份测试 WAV。发布材料保留样本来源与第三方条款尚未独立核实的说明；不上传私人排查录音、原始完整会话、凭据、虚拟环境或模型权重，不覆盖用户手动编辑的参考文本。
